    Brazil Signature Filing Authorization Package — Guivos¶

    1. Finalidade¶

    Este documento prepara o pacote brasileiro de autorização para depósito das duas assinaturas institucionais da Guivos.

    Ele fecha, antes de qualquer protocolo:

    • sinal exato;
    • forma de apresentação;
    • natureza;
    • classe;
    • especificação-alvo;
    • rota de peticionamento;
    • código de serviço;
    • taxa de referência;
    • condição de desconto;
    • titular/cadastro;
    • gates de execução por item;
    • checklist dos quatro pedidos.

    Este documento não autoriza protocolo, não gera GRU, não paga taxa e não declara pedido depositado.

    AUTHORIZATION PACKAGE PREPARED
≠ FILING AUTHORIZED
≠ GRU ISSUED
≠ GRU PAID
≠ APPLICATION FILED
≠ REGISTRATION GRANTED

    2. Titular do pacote¶

    Titular operacional pretendido para os quatro pedidos:

    GUIVOS LTDA
CNPJ 43.530.598/0001-33

    A continuidade empresarial em relação ao nome histórico CLUBE DE VIAGENS E TURISMO LTDA está reconciliada no GKR pelo mesmo CNPJ informado e pelo portfólio GUIVOS já registrado.

    No protocolo, o cadastro e-INPI/GRU deve refletir a razão social vigente e o mesmo CNPJ.

    Regra de execução:

    SE cadastro do pedido ≠ GUIVOS LTDA / CNPJ 43.530.598/0001-33
→ NÃO PROTOCOLAR
→ corrigir/reconciliar cadastro antes do filing

    3. Sinais exatos¶

    3.1 Assinatura global¶

    Possibility, lived.

    Regras:

    • P maiúsculo;
    • lived minúsculo;
    • vírgula preservada;
    • ponto final preservado;
    • sem palavras adicionais;
    • sem GUIVOS incorporada ao sinal neste pedido;
    • sem hashtag.

    3.2 Versão oficial em português¶

    Possibilidade, vivida.

    Regras:

    • P maiúsculo;
    • vivida minúsculo;
    • vírgula preservada;
    • ponto final preservado;
    • sem palavras adicionais;
    • sem GUIVOS incorporada ao sinal neste pedido;
    • sem hashtag.

    4. Forma e natureza dos pedidos¶

    Para os quatro pedidos:

    APRESENTAÇÃO      Nominativa
NATUREZA          Produto e/ou serviço
TITULAR           GUIVOS LTDA
TERRITÓRIO        Brasil
ROTA              pedido nacional direto no INPI

    Não utilizar representação gráfica, logo, lockup, tipografia especial ou composição mista neste pacote.

    MARCA NOMINATIVA
≠ LOCKUP
≠ LOGO
≠ MARCA MISTA

    5. Pedido 1 — Possibility, lived. / classe 35¶

    SINAL          Possibility, lived.
CLASSE         35
APRESENTAÇÃO   Nominativa
DECISÃO        FILE

    Especificação-alvo¶

    Selecionar, se disponíveis como itens pré-aprovados no e-Marcas vigente:

    1. Provimento de mercado on-line para compradores e vendedores de produtos e serviços [marketplace] — referência Nice/base 350120;
    2. Publicidade on-line em rede de computadores — referência Nice/base 350084;
    3. Marketing — referência Nice/base 350106.

    Esses itens formam o escopo autorizado deste pacote para a classe 35.

    Não adicionar outros serviços sem novo controle documental.

    6. Pedido 2 — Possibility, lived. / classe 42¶

    SINAL          Possibility, lived.
CLASSE         42
APRESENTAÇÃO   Nominativa
DECISÃO        FILE

    Especificação-base executável¶

    Selecionar, se disponíveis como itens pré-aprovados no e-Marcas vigente:

    1. Software como serviço [SaaS] — referência Nice/base 420220;
    2. Plataforma como serviço [PaaS] — referência Nice/base 420248.

    Item condicional — AIaaS¶

    Inteligência artificial como serviço [AIaaS] — referência Nice/base 420315 — é um item candidato condicional.

    Ele somente poderá ser incluído neste pedido se, antes da autorização/protocolo, estiver arquivada evidência de que a atividade efetiva/objeto aplicável do titular oferece suporte suficiente ao item.

    AIaaS classificado na classe 42
≠ AIaaS automaticamente autorizado

AIaaS_execution_gate
= EVIDÊNCIA DE ATIVIDADE EFETIVA COMPATÍVEL

    Se a evidência não estiver disponível ou for insuficiente:

    MANTER classe 42 = FILE
MANTER SaaS + PaaS
OMITIR AIaaS
NÃO inventar atividade
NÃO atrasar a classe 42 apenas por esse item

    Não ampliar para consultoria em IA, desenvolvimento para terceiros, blockchain, hospedagem ou outros serviços sem razão própria.

APRESENTAÇÃO   Nominativa

    Usar a mesma especificação-alvo do Pedido 1:

    1. Provimento de mercado on-line para compradores e vendedores de produtos e serviços [marketplace] — 350120;
    2. Publicidade on-line em rede de computadores — 350084;
    3. Marketing — 350106.

    8. Pedido 4 — Possibilidade, vivida. / classe 42¶

    SINAL          Possibilidade, vivida.
CLASSE         42
APRESENTAÇÃO   Nominativa
DECISÃO        FILE

    Usar a mesma especificação-base e o mesmo gate do Pedido 2:

    1. Software como serviço [SaaS] — 420220;
    2. Plataforma como serviço [PaaS] — 420248;
    3. Inteligência artificial como serviço [AIaaS] — 420315 somente se o gate de atividade efetiva estiver satisfeito.

    9. Rota de especificação e código INPI¶

    Rota preferencial¶

    CÓDIGO 389
Pedido de registro de marca com especificação pré-aprovada — valor por classe

    Essa rota é a preferida somente se todos os itens efetivamente autorizados estiverem disponíveis e selecionáveis no e-Marcas no momento real de preparação do pedido.

    O INPI informa que a lista pré-aprovada do e-Marcas é derivada da Classificação de Nice e listas auxiliares, mas que itens podem ser suprimidos da lista operacional.

    Portanto:

    ITEM CONSTA NA NICE
≠ GARANTIA DE QUE ESTÁ SELECIONÁVEL NO e-MARCAS NO DIA DO FILING

    Fallback¶

    CÓDIGO 394
Pedido com especificação de livre preenchimento — valor por classe

    O código 394 não é automaticamente autorizado por este pacote.

    Se qualquer item necessário não estiver disponível na lista pré-aprovada:

    NÃO PAGAR
NÃO SUBSTITUIR SILENCIOSAMENTE
NÃO USAR CÓDIGO 394 AUTOMATICAMENTE
→ revalidar especificação e custo
→ obter nova autorização se o custo/escopo mudar

    10. Taxas oficiais de referência¶

    Tabela INPI vigente consultada em 20/08/2026:

    Código Serviço Valor integral por classe Valor com desconto de 50%, quando elegível
    389 especificação pré-aprovada R$ 880,00 R$ 440,00
    394 especificação livre R$ 1.720,00 R$ 860,00

    Pacote preferencial — código 389¶

    4 pedidos × R$ 880,00 = R$ 3.520,00

    Se o titular estiver validamente enquadrado no desconto de 50% no INPI:

    4 pedidos × R$ 440,00 = R$ 1.760,00

    Fallback — código 394¶

    4 pedidos × R$ 1.720,00 = R$ 6.880,00

    Com desconto elegível:

    4 pedidos × R$ 860,00 = R$ 3.440,00

    11. Estado do desconto¶

    Fontes públicas secundárias consultadas indicam GUIVOS LTDA como MICRO EMPRESA. O INPI prevê desconto de até 50% nos serviços elegíveis para microempresas, microempreendedores individuais e empresas de pequeno porte.

    Isso é suporte preliminar, não substituto do enquadramento reconhecido no cadastro/GRU do INPI.

    Estado:

    discount_candidate = 50_percent
discount_basis = public_ME_indication
INPI_discount_confirmation = required_before_payment

    A autorização futura deverá utilizar um destes cenários:

    CENÁRIO A — desconto confirmado no INPI
código 389
custo total = R$ 1.760,00

CENÁRIO B — desconto não disponível
código 389
custo total = R$ 3.520,00

    Se o sistema exigir código 394, retornar ao gate de autorização antes de pagar.

    12. Checklist comum aos quatro pedidos¶

    Antes de cada protocolo confirmar:

    • titular exibido como GUIVOS LTDA;
    • CNPJ 43.530.598/0001-33;
    • apresentação Nominativa;
    • natureza Produto e/ou serviço;
    • sinal exatamente conforme seção correspondente;
    • classe correta;
    • somente especificações autorizadas;
    • para classe 42: AIaaS incluído somente se houver evidência de atividade efetiva compatível;
    • especificações selecionadas como pré-aprovadas, se código 389;
    • código da GRU coerente com a rota autorizada;
    • desconto confirmado ou negado pelo sistema antes do pagamento;
    • taxa revalidada na tabela vigente;
    • busca marcária revalidada imediatamente antes do filing, se houver intervalo material;
    • nenhuma representação gráfica anexada para pedido nominativo;
    • nenhuma inclusão de hashtag ou bordão;
    • comprovante da GRU arquivado após pagamento;
    • recibo/protocolo arquivado após envio.

    13. Matriz pronta para autorização¶

    # Sinal Classe Apresentação Rota preferida Estado
    1 Possibility, lived. 35 Nominativa 389 READY_FOR_AUTHORIZATION
    2 Possibility, lived. 42 Nominativa 389 READY_FOR_AUTHORIZATION_WITH_ITEM_GATE
    3 Possibilidade, vivida. 35 Nominativa 389 READY_FOR_AUTHORIZATION
    4 Possibilidade, vivida. 42 Nominativa 389 READY_FOR_AUTHORIZATION_WITH_ITEM_GATE

    READY_FOR_AUTHORIZATION_WITH_ITEM_GATE significa que a aplicação de classe 42 está pronta para decisão humana, mas o item AIaaS somente poderá integrar a especificação se a evidência factual exigida estiver presente. Sem ela, a aplicação continua autorizável com SaaS/PaaS.

    Estado agregado:

    signature_clearance = CLEAR
signature_filing_decision = FILE
authorization_package_prepared = true
preferred_route = INPI_389
AIaaS_execution_gate = EVIDENCE_REQUIRED
preferred_total_if_discount_confirmed = R$ 1.760,00
maximum_total_on_389_without_discount = R$ 3.520,00
filing_authorized = false
filed = false
registered = false

    14. O que não integra este pacote¶

    Não integra esta autorização:

    • GUIVOS, já registrada nas classes 09, 35, 39 e 42;
    • #PossibilityLived;
    • Do possível ao vivido.;
    • classes 9, 39, 41, 43 ou 45 das assinaturas;
    • logo ou identidade visual;
    • lockup GUIVOS + assinatura;
    • pedidos internacionais;
    • Sistema de Madri;
    • oposições, recursos ou manifestações futuras.

    15. Próximo gate¶

    O próximo gate é Human Filing Authorization.

    Uma autorização válida deverá declarar explicitamente que está autorizando:

    1. os quatro pedidos acima;
    2. emissão e pagamento das GRUs;
    3. protocolo no INPI;
    4. o teto financeiro aplicável ao cenário confirmado no sistema;
    5. para as classes 42, se AIaaS está incluído com evidência suficiente ou omitido.

    Antes de qualquer pagamento, o executor deverá informar qual cenário foi confirmado:

    A = código 389 + desconto 50% → R$ 1.760,00
B = código 389 sem desconto   → R$ 3.520,00

    Se a rota mudar para código 394, não executar sem nova autorização.
